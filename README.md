# ggstunnel 0.3.0-rc1 — BIP5 Performance

این بسته نامزد انتشار با اولویت BIP است؛ 100/200Mbps روی WAN یا پایداری چندروزه روی Ubuntu هنوز تأیید نشده است. تست‌های محلی و شبیه‌سازی انجام شده‌اند و جزئیات در PERFORMANCE-fa.md آمده است.

BIP5 با BIP3/fix4 و BIP4 سازگار نیست؛ هر دو سرور باید همین بسته را اجرا کنند. محدودیت ثابت نرخ در کانفیگ‌های جدید BIP غیرفعال است، اما کنترل ازدحام، پنجرهٔ محدود 4096 بسته و صف‌های محدود برای پایداری باقی مانده‌اند. هدر DATA همچنان 72 بایت است.

## قابلیت‌ها

- هسته Go با AES-GCM و ترنسپورت‌های BIP، TCP، UDP، ICMP و GRE.
- منوی مدیریت Python3 و نصب پیش‌نیازها؛ Ubuntu 22.04/24.04، Linux amd64/arm64، systemd و TUN لازم‌اند.
- یک سرویس مستقل برای هر ایران↔خارج؛ تا 168 شناسه در طرح فعلی. تست 9 اتصال BIP شبیه‌سازی‌شده و تست‌های محلی TCP/UDP پوشش داده شده‌اند؛ تست همزمان 9 سرور واقعی انجام نشده است.
- تخصیص ggs01 = 10.88.1.1 ↔ 10.88.1.2؛ ggs02 = 10.89.1.1 ↔ 10.89.1.2؛ تا ggs09 = 10.96.1.1 ↔ 10.96.1.2.
- کد اتصال شامل PSK اختصاصی، IPv4ها، پورت، نوع تانل و تنظیمات مشترک. نیازی به انتقال فایل کانفیگ نیست. کد محرمانه است؛ Base64 رمزنگاری نیست و checksum فقط خطای کپی را تشخیص می‌دهد. آن را فقط از سرور ایران خودتان دریافت کنید و منتشر نکنید.
- فوروارد TCP/UDP از هر سمت به IP داخلی سمت مقابل؛ حداکثر 128 قانون و 1024 اتصال/نشست برای هر قانون.
- ویرایش، restart، حذف، backup کانفیگ و بازیابی؛ عملیات تکی یا گروهی؛ آپدیت از بستهٔ استخراج‌شده و rollback نسخه.
- گزارش متنی، تست ظرفیت پله‌ای و تست مداوم. گزارش‌ها کانفیگ و PSK را ذخیره نمی‌کنند.

این انتشار به بخش TUN و فوروارد آن اختصاص دارد. quantum و quantum+ در این نسخه ارائه نشده‌اند. GRE این برنامه حامل رمز‌شدهٔ مخصوص ggstunnel است؛ سمت مقابل هم باید همین برنامه باشد، نه یک GRE عادی MikroTik یا ip tunnel.

## نصب روی هر دو سمت

روی هر دو سرور اجرا کنید:

```bash
sudo apt-get update
sudo apt-get install -y git ca-certificates
sudo git clone https://github.com/MmdHoss3in/ggstunnel.git /opt/ggstunnel-src
cd /opt/ggstunnel-src
sudo bash setup.sh
```

نصاب از مخازن Ubuntu این پیش‌نیازها را نصب می‌کند: python3، iproute2، iputils-ping، iperf3، nano، kmod، procps، ca-certificates و unzip. Go روی سرور لازم نیست.

برای بازکردن دوبارهٔ منو:

```bash
sudo ggstunnel
```

باینری‌های آمادهٔ amd64 و arm64 در `dist/` هستند. `setup.sh` به کل پوشهٔ ریپو نیاز دارد؛ دانلود تنها همین اسکریپت کافی نیست. اگر پوشهٔ `/opt/ggstunnel-src` از قبل clone شده، دستور clone را دوباره اجرا نکنید؛ از بخش آپدیت استفاده کنید.

اگر نسخهٔ آزمایشی قدیمی روشن است، پیش از تست اتصال جدید آن را متوقف کنید:

```bash
cd /root/ggstunnel-develop/source
sudo bash setup.sh develop stop
```

نصاب به تانل‌های AmneziaWG، WireGuard و سایر سرویس‌ها دست نمی‌زند.

## ساخت ایران و اتصال خارج

1. روی ایران، گزینهٔ 1: Create Iran tunnel.
2. ترنسپورت را انتخاب کنید. پیش‌فرض این نسخه BIP5 است. سقف ثابت 10هزار pps در تنظیمات جدید غیرفعال شده؛ نرخ واقعی با ACK، RTT و کنترل ازدحام تعیین می‌شود.
3. IPv4 عمومی ایران و آن سرور خارج را وارد کنید. IPv4 ایران باید روی همین میزبان قابل bind باشد. برای TCP/UDP پورت مستقل، مثلاً 24001، انتخاب کنید.
4. برنامه PSK تصادفی 256بیتی می‌سازد، سرویس را فعال می‌کند و کد GGS2 را نمایش می‌دهد.
5. روی خارج، گزینهٔ 2: Join from foreign؛ همان کد را paste کنید. ورودی به‌صورت مخفی است. IPv4 محلی خارج از route ایران استخراج می‌شود.
6. برای خارج بعدی همین روند را در ایران تکرار کنید؛ شناسه و شبکهٔ بعدی اختصاص داده می‌شود.

خودکارسازی کد اتصال، firewall ارائه‌دهنده یا محدودیت مسیر را برطرف نمی‌کند. برای TCP، پورت انتخاب‌شده روی ایران باید از IP خارج مجاز باشد. UDP با endpoint ثابت کار می‌کند: همان پورت در هر دو سمت از IP همتا مجاز باشد. ICMP/BIP به ICMP و GRE به پروتکل IP شمارهٔ 47 نیاز دارد. UDP این نسخه برای دو VPS با IPv4 عمومی ثابت است؛ roaming پورت NAT پیاده‌سازی نشده است. قوانین firewall عمومی، AWG و nftables موجود بازنویسی نمی‌شوند.

## منو

| گزینه | کار |
|---|---|
| 1 / 2 | ایجاد روی ایران / اتصال یا جایگزینی کانفیگ در خارج |
| 3 | وضعیت سرویس و فعال‌بودن پس از reboot |
| 4 / 5 | Start / Stop موقت، بدون تغییر وضعیت boot |
| 6 | Restart |
| 7 / 8 | روشن‌کردن همراه boot / خاموش‌کردن همراه غیرفعال‌سازی boot |
| 9 | ویرایش JSON، افزودن یا حذف فوروارد، بازیابی کانفیگ قبلی |
| 10 | حذف تانل انتخابی؛ backup خصوصی باقی می‌ماند |
| 11 | نمایش مجدد کد اتصال روی ایران |
| 12 / 13 | لاگ / گزارش متنی عیب‌یابی |
| 14 / 15 | listener تست روی ایران / تست پله‌ای روی خارج |
| 16 / 17 | اعمال / بازگردانی tuning شبکه |
| 18 / 19 | آپدیت از پوشهٔ source نسخهٔ جدید / rollback نسخهٔ قبلی نصب‌شده |
| 21 | اعمال تنظیمات کارایی BIP روی تانل‌های موجود؛ backup گرفته می‌شود |
| 20 | تست مداوم TCP/UDP در دو جهت، هرکدام 10 دقیقه؛ مجموع حدود 40 دقیقه |

گزینه‌های 4 تا 8 نامی مثل ggs01 یا `all` را می‌پذیرند. Stop موقت، سرویس را تا Start دستی یا reboot متوقف نگه می‌دارد؛ گزینهٔ OFF برای خاموشی ماندگار است. RUNNING صرفاً وضعیت پروسه است؛ برای بررسی اتصال از گزارش ping و آمار استفاده کنید.

```bash
sudo ggstunnel status
sudo ggstunnel stop ggs01
sudo ggstunnel start ggs01
sudo ggstunnel restart ggs01
sudo ggstunnel off all
sudo ggstunnel on all
sudo ggstunnel stop all
sudo ggstunnel diagnose all
```

برای ویرایش مشترک PSK/ترنسپورت/پورت/MTU، تنظیمات هر دو سمت باید یکسان شوند؛ کد تازه را روی خارج با گزینهٔ 2 و REPLACE اعمال کنید. فورواردهای خارج هنگام REPLACE حفظ می‌شوند. ویرایش شناسهٔ تانل ممنوع است. ویرایش تانل متوقف‌شده آن را روشن نمی‌کند.

## فوروارد

در گزینهٔ 9، زیرگزینهٔ 2 را انتخاب کنید. مثلاً روی ایران، listen = 0.0.0.0:1021 و مقصد = پورت 1021 همتا؛ مقصد به‌صورت خودکار 10.88.1.2:1021 خواهد بود. سرویس مقصد روی خارج باید به IP داخلی یا 0.0.0.0 bind باشد. TCP و UDP قانون‌های جداگانه‌اند. پورت ورودی این سرویس را در firewall متناسب با مصرف خود مجاز کنید.

فوروارد داخل همان پروسه اجرا می‌شود و با توقف تانل بسته می‌شود؛ NAT و ip_forward برای این نوع فوروارد پروکسی لازم نیست. عبور مستقیم subnetهای دیگر نیازمند تنظیم جداگانهٔ routing/firewall است.

## منابع و tuning

هر تانل پروسهٔ جدا دارد. GOMAXPROCS در سرویس تعیین نمی‌شود؛ Go از پیش‌فرض زمان اجرا استفاده می‌کند. محدودیت ثابت دو هسته از unit حذف شده است. این موضوع تضمین ظرفیت نیست. بافر سوکت در کانفیگ 4MiB و صف 4096 بسته است؛ افزایش صف به‌تنهایی سرعت مسیر را افزایش نمی‌دهد.

گزینهٔ 16 سقف بافرهای سوکت را تا حداقل 16MiB و tcp_mtu_probing را تا حداقل 1 بالا می‌برد. مقدار بزرگ‌تر موجود حفظ می‌شود؛ تنظیمات قبلی برای بازیابی ذخیره می‌شوند. BBR، rp_filter، firewall و default route تغییر نمی‌کنند. گزینهٔ 17 تنها مقادیری را برمی‌گرداند که پس از tuning توسط ابزار دیگری تغییر نکرده باشند.

Tuner تطبیقی فقط مخصوص BIP است. TCP از کنترل ازدحام TCP سیستم‌عامل استفاده می‌کند. UDP، ICMP و GRE خام بازفرست خودکار مستقل در سطح carrier ندارند؛ رفتار packet loss آن‌ها مثل BIP نیست. دادهٔ داخلی TCP می‌تواند بازفرست خودش را انجام دهد، UDP داخلی چنین تضمینی ندارد.

## تست لازم برای تصمیم stable

برای ggs01 روی ایران:

```bash
sudo ggstunnel listen ggs01
```

روی خارج:

```bash
sudo ggstunnel capacity ggs01
```

پله‌ها 5،20،50،80،100Mbps، هر آزمایش 30 ثانیه، TCP و UDP در دو جهت و به‌صورت ترتیبی‌اند. اگر دریافت کمتر از 80٪ هدف یا loss بیش از 1٪ باشد، پلهٔ بالاتر اجرا نمی‌شود. عبور یک پله صرفاً آزمون اولیه است؛ اثبات پایداری نیست. مثلاً عبور پلهٔ 100 با این آستانه الزاماً دریافت کامل 100Mbps نیست.

بعد از پایان خارج، listener ایران را Ctrl+C کنید. هر دو سمت در خط REPORT مسیر ZIP را چاپ می‌کنند؛ آن دو فایل را بفرستید. گزارش متنی نیز با `sudo ggstunnel diagnose ggs01` ساخته می‌شود. فایل‌ها زیر /etc/ggstunnel/reports قرار دارند.

بعد از عبور پله‌ها، گزینهٔ 20 را روی خارج با نرخ مورد نظر اجرا کنید و listener ایران را روشن بگذارید. برای سنجش مجموع بار ایران، همین آزمایش را روی همهٔ همتاها به‌طور همزمان اجرا کنید؛ تست محلی این بسته جایگزین آن نیست. همچنین reboot دو سمت، قطع و بازگشت شبکه، فوروارد و توقف/روشن‌کردن گروهی باید در محیط واقعی تأیید شوند.

## آپدیت و بازیابی

روی هر دو سمت:

```bash
cd /opt/ggstunnel-src
sudo git pull --ff-only
sudo bash setup.sh
```

`git pull` فقط فایل‌های منبع را دریافت می‌کند؛ اجرای `setup.sh` نسخهٔ نصب‌شده را عوض می‌کند. کانفیگ عملیاتی بیرون از checkout نگهداری می‌شود؛ فایل‌های ریپو را برای تغییر تانل ویرایش نکنید و از منو استفاده کنید. اگر pull به علت تغییرات محلی متوقف شد، تغییرات را بررسی کنید؛ برای رفع آن از reset اجباری استفاده نکنید.

برای ارتقا از BIP3/BIP4، قبل از نصب در هر دو سمت `sudo ggstunnel stop all` بزنید؛ سپس نسخهٔ جدید را روی هر دو سمت نصب کنید، گزینهٔ 21 را برای کانفیگ‌های موجود اجرا کنید و با `sudo ggstunnel on all` روشن کنید. این ارتقا قطع اتصال دارد. برای اولین مهاجرت از نصب ZIP، ابتدا ریپو را مطابق بخش نصب clone کنید.


نسخه‌های نصب‌شده در /opt/ggstunnel/releases و کانفیگ‌ها در /etc/ggstunnel/tunnels با دسترسی خصوصی نگهداری می‌شوند. گزینهٔ 18 مسیر ریشهٔ ریپو یا پوشهٔ `source` بستهٔ استخراج‌شدهٔ جدید را می‌گیرد؛ checksum فایل‌ها و سازگاری کانفیگ‌ها را بررسی می‌کند و فقط سرویس‌های درحال اجرا را restart می‌کند. با شکست راه‌اندازی فوری، نسخهٔ قبلی برمی‌گردد. این بررسی اتصال WAN را تأیید نمی‌کند.

گزینهٔ 19 به نسخهٔ نصب‌شدهٔ قبلی برمی‌گردد؛ اولین نصب نسخهٔ قبلی ندارد. بازیابی کانفیگ مستقل در گزینهٔ 9 است. فایل‌های backup حاوی PSK هستند و برای ارسال گزارش مناسب نیستند. checksumها تشخیص خرابی فایل‌اند، نه امضای ناشر؛ بسته را از منبع مورد اعتماد دریافت کنید.

TCP این انتشار handshake تازه دارد و UDP از پورت ثابت استفاده می‌کند؛ هر دو سمت را با همین بسته نصب کنید. BIP wire این بسته BIP5 است. کد اتصال جدید GGS2 است؛ کدهای قبلی را برای ایجاد تانل جدید استفاده نکنید.

## ساخت از سورس

نسخهٔ Go موردنیاز در `go.mod` مشخص است. ساخت باید روی Linux با Go و Python3 انجام شود:

```bash
bash scripts/build-release.sh
```

اسکریپت تست و vet را اجرا می‌کند، باینری‌های دو معماری و checksumهای بسته را می‌سازد. برای نصب معمولی نیازی به ساخت نیست. گزارش آزمون‌های نسخه در [PERFORMANCE-fa.md](PERFORMANCE-fa.md) است؛ این گزارش مربوط به آزمون‌های پیش از انتشار است.
